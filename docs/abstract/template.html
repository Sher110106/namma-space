Position. Namma Space puts measured fidelity on phone-only input beside a browser twin that behaves like a place. We report the camera path, scale interval, held-out image scores, wall tests and device timings from the run record.

Capture SOP and quality gates

Three passes

Take A starts at the doorway, follows an outer wall loop, an inner loop facing the walls, and a low pass around the floor and furniture. At each corner the phone looks to the ceiling corner. Take B repeats the room, crosses the door slowly, covers the next space and returns. The phone stays on the one-times lens, in landscape, with focus, exposure and white balance locked.

Check and ingest

./ns check reads metadata, blur and luma. It returns PASS, WARN or FAIL and prints the time range to reshoot. Ingest decodes rotation, tone maps HDR when needed, samples the video, keeps sharp frames, removes near duplicates and writes the selected images in capture order.

What the four SOP items mean

Camera angles: outer, inner and low passes. Corner shots: tilt-ups. Floor plan: the hand sketch is an input; the grid and minimap are computed outputs. Sensors: phone camera only, by choice.

Scale rule. Gravity and a floor plane set the frame. Camera height, optional metric depth and tape checks are fused in log space. The result is an interval, carried as T_final; a rescale does not retrain the splats.

Pipeline and technical approach

Poses and alignment

COLMAP runs an ALIKED plus LightGlue path and a CPU SIFT plus LightGlue path. A global mapping pass can reuse the best database. We choose the largest valid model by registration, reprojection error and point count, then undistort to a pinhole model. The race makes a broken room visible early and keeps the fallback local.

Appearance and geometry

gsplat trains MCMC splats with world normalisation off, anti-aliasing and a bilateral grid. Held-out poses choose the variant. Export removes invalid, opaque, huge and camera-bubble splats, then writes compact SPZ files. A light grid from the splats supplies walk collision, spawn and the minimap; the splat remains the renderer.

Browser path

Spark renders the SPZ asset and three.js carries the camera convention. The scene bundle stores the transform, floor, scale interval, bookmarks, tour and held-out photo poses. The viewer loads a small preview before the standard file and lowers quality when a device needs it.

Failure handling

Each stage writes its JSON only after its temporary output is complete. A partial SfM model is labelled. Training keeps the measured variant. Export, grid and viewer validators reject missing files, bad counts, wrong grid values and convention errors. The offline bundle and video remain available when a hosted page is unavailable.

Limits. The capture has no LiDAR input. Public-room comparisons are evaluation evidence, not claims about a user's room. Device results are tied to the recorded browser and GPU. The current viewer does not search places or draw routes.

Evidence keys

Run record: report.json, stage timings: timings.json, and evaluation files under eval/results/*.json. Every numeric field on this page comes from those records.

Bottlenecks and compute request

The shared GPU spends time in feature matching and splat optimisation. A larger queue of quiet GPUs would reduce the wait for the SfM race, two training variants, and the public-room checks. The requested resource is a measured, local batch slot with enough memory for the selected SPZ export; the run log reports the actual need after capture.

Data and code

MuSHRoom, Mip-NeRF 360 and the other public rooms are credited in LICENSES.md and used for evaluation only. User input is published only after sign-off. The repository is Apache-2.0. The viewer vendor directory carries the Spark and three.js notices.
